# Spécifications — XpertSphere.MonolithApi

Un fichier Markdown par fonctionnalité spécifiée (nommage `<slug-fonctionnalite>.md`), rédigé par l'agent spec-writer avant tout développement.

Spécifications existantes :
- `azurite-blob-storage-local.md` — stockage Blob (CV/documents) en local via Azurite, coexistant avec la configuration Azure Storage réelle de Staging/Production.
- `secure-cv-download.md` — endpoint proxy authentifié pour consulter/télécharger un CV déjà uploadé (candidat propriétaire + rôles d'organisation), avec section de coordination frontend (`candidate-app`, `recruiter-app`).
- `candidate-registration-experience-description-error.md` — rend obligatoire la description d'une expérience à l'inscription candidat (`POST /api/auth/register/candidate`) avec message d'erreur explicite (numéro/titre de l'expérience), et corrige l'affichage du message générique côté frontend ; coordination avec `candidate-app`.
- `login-response-missing-experiences-trainings.md` — `LoginAsync`/`RefreshTokenAsync` ne chargent pas `Experiences`/`Trainings`/`Address` contrairement à `GetCurrentUserAsync`, profil candidat visuellement incomplet jusqu'à un reload ; coordination avec `candidate-app`.
- `seed-demo-organizations-users-joboffers.md` — extension du seeder existant (`DatabaseExtensions.cs`), borné à l'environnement Development, pour pousser 3 organisations clientes de démonstration avec leur roster d'utilisateurs, 30 offres d'emploi, 4 candidats et leurs candidatures.
- `enrich-seed-candidate-profiles.md` — extension de `SeedDemoCandidatesAsync` : 2 `Experience` + 1 `Training` réalistes par candidat, champs scalaires `User` restés vides (`PhoneNumber`, `LinkedInProfile`, `Skills`, `YearsOfExperience`, `DesiredSalary`/`DesiredSalaryCurrency`, `Availability`), `Address` complète par candidat, et correction de `ProfileCompletionPercentage` (jamais calculée sur le chemin de seed) ; logique "renseigner seulement si vide" pour ne jamais écraser une modification faite depuis l'application et enrichir rétroactivement une base déjà seedée ; upload de CV explicitement exclu (contrainte utilisateur) ; signale une incohérence de nommage de champs préexistante côté `recruiter-app` (`Experience`), hors périmètre de cette spec.
- `configurable-salary-currency.md` — nouvel enum `Currency` (EUR/XOF) contrôlé, devise configurable par organisation (`Organization.Currency`, snapshot figé sur `JobOffer.SalaryCurrency` à la création, non rétroactif) et devise auto-déclarée par le candidat (`User.DesiredSalaryCurrency`), avec nouvel endpoint self-service `GET/PUT /api/organizations/me/currency` réservé à `Organization.Admin` ; coordination avec `seed-demo-organizations-users-joboffers.md`, `candidate-app` et `recruiter-app`.
- `role-user-count-organization-scope-fix.md` — `RoleDto.UsersCount` (`GET /api/Roles/paginated`, `RoleService.BuildRoleQuery`) compte les utilisateurs de toutes les organisations au lieu de scoper à l'organisation de l'appelant non-plateforme (`Organization.Admin`/`Manager`) ; même correctif de cohérence appliqué à `UserRoleService.GetRoleUsersAsync`, bug latent aujourd'hui (endpoint restreint aux profils plateforme, dialog non câblé côté `recruiter-app`) ; coordination informative avec `recruiter-app`.
- `french-message-consistency.md` — traduction en français des messages utilisateur du backend (`Constants.cs`, `Validators/**`, et sous réserve de confirmation `Services/*.cs`/`Controllers/*.cs`), correction de résidus anglais côté frontend (page 404, listes de compétences) et du défaut de locale `en-US` du scaffold `vue-i18n` inutilisé ; coordination avec `candidate-app`/`recruiter-app`.
- `candidate-account-activation-email.md` — ticket B de `email-sending-foundation.md` (`XpertSphere.CommunicationService`) : génération réelle du lien d'activation à l'inscription candidat (`POST /api/auth/register/candidate`), appel HTTP vers `CommunicationService` (`POST /api/emails/send`), correctif du provider de token Identity (fenêtre TOTP trop courte pour un lien envoyé par email) ; **activation stricte** (`RequireConfirmedEmail = true`, décision utilisateur), nouvel endpoint `POST /api/auth/resend-confirmation` (enumeration-safe, cooldown par email + rate limiting par IP), migration de grandfathering des comptes existants non confirmés ; aucun changement côté `CommunicationService` ; coordination avec `candidate-app` (nouvelle page `/confirm-email`, bandeau de renvoi sur `LoginPage.vue`).
